# กระทุ่มแบนไปด้วยกัน — Admin ร้านค้า 4 แท็บ (R2)

วันที่จัดทำ: 29 ต.ค. 2569

## เป้าหมาย

ลดความรกของหน้า Admin Center → ร้านค้า โดยแยกร้านตามสถานะ ไม่ต้องแสดงร้านที่ไม่อนุมัติปะปนกับร้านที่ใช้งานอยู่

## การทำงาน

- เปิดหน้าแรกที่แท็บ **✅ เปิดใช้งาน** (เฉพาะสถานะ `approved`)
- **⏳ รออนุมัติ** (`pending`) — กดอนุมัติหรือไม่อนุมัติจากแท็บนี้
- **🗃️ ปิดใช้งาน** (`archived`) — กดกู้คืนร้านได้ด้วยปุ่มเดิม
- **❌ ไม่อนุมัติ** (`rejected`) — เก็บร้านที่ปฏิเสธไว้และยังมีปุ่มอนุมัติใหม่
- แสดงจำนวนร้านในแต่ละแท็บ ค้นหาตามชื่อร้าน/รายละเอียดภายในแท็บที่เลือก
- หลังเปลี่ยนสถานะ ร้านจะย้ายจากแท็บเดิมไปยังแท็บสถานะใหม่หลังโหลดข้อมูลอีกครั้ง

## ไฟล์ที่ให้ใช้

1. `app.js` — สืบต่อจาก `ktb-admin-shop-archive-20261029/app.js` (R1) โดยเพิ่มการแยกแท็บใน Admin เท่านั้น
2. `index.html` — สืบต่อจาก `ktb-admin-shop-archive-20261029/index.html` และเพิ่มสไตล์แท็บ + เปลี่ยนเวอร์ชันโหลด `app.js`

**ไม่ต้องรัน SQL เพิ่ม** ไม่มีการเปลี่ยนฐานข้อมูล, RPC, Trigger, ออเดอร์, การจ่ายเงิน หรือระบบ Rider ในชุด R2 นี้

หมายเหตุ: ปุ่มปิดใช้งาน/กู้คืนยังเรียก RPC `market_admin_set_shop_archived` เดิม หาก Staging ติดตั้ง RPC จากชุด R1 แล้ว จะใช้งานต่อได้

## วิธีทดสอบบน Staging

1. สำรอง `app.js` และ `index.html` บน GitHub Staging ปัจจุบัน
2. อัปโหลดสองไฟล์ในชุดนี้แทนไฟล์ชื่อเดียวกันที่ **root ของ Staging เท่านั้น**
3. รอ GitHub Pages อัปเดต จากนั้นเปิดหน้า Staging → Ctrl + Shift + R
4. ลงชื่อเข้าใช้ Admin → Admin Center → ร้านค้า
5. ตรวจว่าเปิดมาเจอ **เปิดใช้งาน** เท่านั้น และอีก 3 แท็บแสดงรายการตามสถานะ
6. ตรวจว่าจำนวนร้านตรงกับข้อมูลจริง ปุ่มค้นหาทำงาน และการกดปุ่มอนุมัติ/ไม่อนุมัติ/ปิดใช้งาน/กู้คืนยังทำงานเหมือนเดิม
7. ใช้ร้านทดลองเท่านั้นในระหว่างทดสอบ และตรวจว่าหน้าลูกค้า/ระบบสั่งซื้อ/Rider ยังทำงานเหมือนก่อนแก้

## ย้อนกลับ

อัปโหลดไฟล์ `app.js` และ `index.html` ที่สำรองไว้ก่อนทำ R2 กลับไปทั้งคู่ แท็บจะกลับเป็นรายการร้านแบบเดิม ไม่มีข้อมูลร้านถูกเปลี่ยนโดยโค้ดแท็บนี้

## การตรวจ

- `node --check app.js`: ตรวจตอนจัดทำ
- ไม่ได้ Deploy Staging/Production และยังไม่ได้ทดสอบ UI ผ่านบัญชี Admin จริง
